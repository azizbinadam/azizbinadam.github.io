Integrated Design Project · 2025

Real-Time PPE Compliance Monitoring System

An academic AI and IoT system that combines computer vision-based PPE monitoring with cloud-mediated communication and automated machine-control responses.

Project Type University Capstone · Group Project
Role Project Supervisor · Software & System Design
Date March – July 2025

Overview

Connecting computer vision with physical safety control

The Real-Time PPE Compliance Monitoring System was developed as a group project for EEE630 – Integrated Design Project at Universiti Teknologi MARA (UiTM).

The system combines two main subsystems. The first uses a Raspberry Pi 5 and camera to perform AI-based PPE detection and tracking. The second uses an ESP32-based control unit to translate the resulting safety status into physical machine responses.

Rather than treating computer vision as an isolated monitoring tool, the project explored how detection results could be communicated through an IoT architecture and used to trigger a machine-control response.

The Problem

From PPE detection to an actionable safety response

Manual PPE compliance monitoring can be inconsistent and reactive. A monitoring system that only identifies a violation still leaves the physical response to a human operator.

The project therefore explored an integrated approach in which PPE detection could become part of an automated safety-control workflow.

Challenge

Detect PPE compliance and proximity to hazardous equipment while connecting the result to a physical control response.

Proposed Approach

Combine edge computer vision, cloud-mediated communication, and embedded machine control into one modular system.

System Architecture

A modular, cloud-mediated architecture

The system was divided into an AI monitoring subsystem and a machine-control subsystem. Instead of directly wiring the two systems together, detection results were passed through a cloud-based data layer.

System Layers

INPUT

Camera Feed

Raspberry Pi Camera V2 provides the live video input used by the AI monitoring subsystem.

↓ Video Stream
AI PROCESSING

Raspberry Pi 5 · YOLOv8 · DeepSORT

PPE detection, person tracking, proximity estimation, and violation decision logic are performed on the Raspberry Pi.

↓ Detection Status
DATA LAYER

Google Sheets · REST API

Detection status is logged to Google Sheets and made available to the machine-control subsystem through REST-based communication.

↓ Safety Status
CONTROL

ESP32 Machine-Control Subsystem

The ESP32 polls the cloud data and translates the safety status into motor, buzzer, and LED responses.

Camera → Raspberry Pi → Google Sheets → REST API → ESP32 → Physical response

Software & AI

Edge AI, tracking, dashboard and data integration

The software stack combined computer vision, embedded computing, web technologies and cloud communication into a single workflow.

Computer Vision

YOLOv8 was used for object detection, while DeepSORT provided multi-object tracking so individuals could maintain consistent tracking identities across frames.

Raspberry Pi

The Raspberry Pi 5 acted as the edge-processing platform for camera input, AI inference, tracking and safety-status generation.

Dashboard

A Flask-based web dashboard provided a live interface for viewing annotated video and system status.

Cloud Logging

Google Sheets was used as the central logging layer for detection and safety-status data.

REST/API Communication

The system used HTTP-based communication to make detection status available to the ESP32 control subsystem.

Embedded Control

The ESP32 interpreted the received safety status and controlled the motor, buzzer, and indicator LEDs.

System Workflow

From detection to machine response

The workflow was structured so that the computer-vision subsystem could make a safety decision independently, while the machine-control subsystem handled the physical response.

01

The camera provides a live video stream of the monitored environment.

02

Proximity Bounding-box-based proximity estimation.
03

Log & Communicate

The resulting safety status is logged and communicated through the cloud layer.

04

Control

The ESP32 polls the status and applies the corresponding machine-control response.

Detection → Decision → Cloud Log → Polling → Actuation

Hardware & Control

Translating software decisions into physical responses

The hardware subsystem provided the physical control layer of the project. It was implemented around an ESP32 microcontroller and connected to the machine response components.

ESP32

The ESP32 acted as the control processor, polling the cloud-mediated safety status and translating it into GPIO-level actions.

Motor Control

A motor and driver circuit were used to represent the controlled machine response during the prototype demonstration.

Safety Indicators

Red and green LEDs together with an audible buzzer provided visual and audible indications of the system state.


Team implementation
