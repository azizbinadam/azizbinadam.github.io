Overview

A software approach to missing-person detection

OneTracer is a software-based proof of concept exploring how computer vision and artificial intelligence can assist in the detection and identification of missing persons.

Rather than developing dedicated hardware, the project is built as a browser-accessible application backed by a Python detection pipeline. Its core design lets an investigator register a missing person from whichever reference material is actually available — CCTV footage, an identification photograph, or both — and adapts the matching logic accordingly.

The system was evaluated against recorded indoor CCTV footage to examine detection accuracy, identity tracking, and behaviour under realistic, uncontrolled lighting conditions.

System Interface

A browser-accessible investigation workflow

OneTracer provides a browser-based interface for registering missing-person profiles, supplying reference material, uploading recorded footage, and reviewing the resulting detection output.

The Problem

Why OneTracer?

Investigators searching for a missing person rarely have consistent reference material to work with. Sometimes hours of CCTV footage exist but no usable photograph of the person can be found; other times a single identification photograph is available with no matching footage at all. Most detection systems are built around one fixed type of reference data, typically a facial photograph, and degrade badly outside that assumption.

OneTracer explores whether a matching system can accept either type of reference material at registration time and adapt its confidence scoring to whichever one it was actually given, rather than forcing both cases through the same formula.

Challenge

Reference material is inconsistent: sometimes footage without a photo, sometimes a photo without footage.

Proposed Direction

Accept either reference type at registration and route each profile through matching logic suited to what it actually has.

System Architecture

A software-only computer vision pipeline

OneTracer is structured as a browser-accessible application, a Flask REST API and computer vision pipeline running behind a single-page dashboard, rather than a standalone script. Its matching logic is deliberately split into two paths depending on what reference material is available for a given profile, CCTV footage or an identification photograph, shown below.

Video Pre-Processing

Optional grayscale and gamma-correction toggles are applied to the footage before detection begins.

03

Detection & Matching

Every tracked person, in every frame, is scored against every registered profile.

Scenario A Weighted-sum score across face, body, colour, and height
Scenario B Tiered fallback — live face, then cached face, then clothing and height
04

Results & Logging

A per-frame CSV log, timestamped evidence crops, and an annotated output video are generated for every profile.

A match is confirmed only once three conditions hold at once: a resolved identity, a confidence score above the matching threshold, and at least three consecutive tracked frames.

Implementation

Building the software proof of concept

The implementation focused on developing the software pipeline required to analyse recorded security footage. The project explored the integration of computer vision and artificial intelligence techniques without relying on dedicated hardware.

Detection & Tracking

YOLOv8n person detection with BoT-SORT tracking, run together as a single pass over every frame of footage.

Re-Identification & Face Matching

OSNet body-appearance embeddings and ArcFace facial embeddings, combined through the context-aware matching logic described above.

Web Application

A Flask REST API and browser dashboard handle profile registration, video upload, and results review, deployed as a single Python process.

Results & Evaluation

Measured results across five individuals, two matching paths

OneTracer was tested using existing recorded indoor security footage rather than a live surveillance environment. This provided a controlled way to examine the behaviour of the software pipeline using realistic visual inputs.

Five individuals were registered across three separate test videos, three profiles built from CCTV footage and evaluated together in a single detection run, and two built from identification photographs and evaluated against a second video under harder, uneven lighting conditions. Detection logs were scored frame by frame against manually verified ground truth.

Because OneTracer was developed as a proof of concept, the goal of this evaluation was to characterise where each matching path succeeds and where it breaks down, rather than to present the system as production-ready. Results varied meaningfully between individuals and between the two registration paths.

Key Findings

01

The two matching paths behave differently, as designed. Scenario A's weighted-sum scoring produced consistently higher recall across all three subjects, while Scenario B's tiered face-first logic produced the highest single-subject precision recorded in the evaluation (Person D) alongside its lowest recall, exactly the trade-off the two-path design was built to isolate rather than average away.

02

Identity switches tracked scene crowding, not scenario type. Scenario A's three simultaneously tracked individuals produced 8–12 ID switches per person, well above Scenario B's 1–5, consistent with appearance-based tracking being more easily confused when more registered people share the frame.

03

Clothing-colour matching is lighting-dependent. Enabling gamma correction left Person D's results almost unchanged but collapsed Person E's recall to roughly a fifth of baseline, traced to where each person's registered anchor colour sits relative to shadow tones under that correction.

A note on scope

This was a proof-of-concept evaluation: five individuals across three videos, with ground truth manually annotated by a single reviewer rather than cross-checked by a second annotator. The results above should be read as evidence the two-path design behaves as intended, not as production-scale accuracy figures.
